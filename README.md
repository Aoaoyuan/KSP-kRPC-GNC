# KSP kRPC Reusable Heavy GNC

一套面向《Kerbal Space Program 1》的 Python/kRPC 实验项目，用于三芯重型
火箭自动发射、侧助推器同步返场、中央芯下程回收，以及任务回顾片风格的自动
摄影。代码保留了较完整的中文注释，目标之一是作为 GNC（制导、导航与控制）
学习材料。

> 这是针对特定 KSP 火箭与分级结构实飞迭代的实验代码，不是适用于任意载具的
> 通用自动驾驶。执行脚本会点火、分级和控制载具；请先备份存档并运行只读检查。

## 已实现能力

- 三芯共 21 台一级发动机点火和连续重力转弯。
- 左右侧芯按燃料储备同时分离，并在安全间距和姿态条件满足后同步返场点火。
- 两枚侧芯使用独立后台油门、栅格舵、末段制导和着陆腿完成同时回收。
- 中央芯尽量完成载荷推送，在保留最低回收燃料后与上面级/载荷分离。
- 载荷分离后完全交给玩家；脚本不点燃上面级，也不编写载荷入轨逻辑。
- 中央芯使用短再入点火、大气减速和一次连续末段着陆点火回收到下程陆地。
- 玩家误触时间加速时，脚本会在不安全阶段恢复 1×，但正式任务不会主动加速。
- 独立事件摄影导演可自动拍摄起飞、三芯分离、同步返场点火、双芯着陆、
  中央芯回收和载荷结尾，并生成剪辑时间标记 CSV。

## 环境要求

- Windows 10/11
- Kerbal Space Program 1.12.x
- Python 3.10 或更新版本
- [kRPC](https://krpc.github.io/krpc/) KSP 模组及 Python 客户端 0.6.0
- Physics Range Extender：三枚相距较远的芯级需要同时保持物理模拟时强烈建议安装

安装 Python 依赖：

```bash
python -m pip install -r requirements.txt
```

启动 KSP 存档后，在 kRPC 窗口启动服务器。首次使用应先执行只读检查：

```bash
python MyHeavyLaunch.py
```

检查应识别到以下液体发动机分组：

```text
左侧芯 / 右侧芯 / 中央芯 = 7 / 7 / 7；上面级发动机数量不限
```

程序从控制器的分离级识别三芯，再检查实际发动机和分离器的动作级。
支持点火→侧芯分离→中央芯分离的连续三级（例如 4→3→2 或 3→2→1），
不再要求固定级号。三芯各需一个独立控制器，侧芯位于载具参考系 X 轴两侧，
各带 4 枚同分离级启动的小火箭；载荷需有不随芯级分离的控制器。
载荷发动机必须安排在中央芯分离之后，入轨仍由玩家操控。
这不是任意火箭通用程序：发动机数量、布局、转弯曲线与回收参数仍针对本项目三芯箭标定。

确认只读检查通过、火箭处于发射前状态后才能执行任务：

```bash
python MyHeavyLaunch.py --execute
```

## Windows 双击入口

启动脚本按以下顺序查找 Python：

1. 项目根目录中未提交的 `local-python.cmd`；
2. Windows Python Launcher：`py -3`；
3. PATH 中的 `python`。

如果需要指定解释器，在项目根目录新建 `local-python.cmd`：

```bat
@echo off
set "KSP_PYTHON=C:\Path\To\Python\python.exe"
```

可用入口：

- `StartHeavyFlight.cmd`：普通三芯自动任务。
- `StartCinematicFlight.cmd`：一遍式摄影预览。
- `StartCinematicMaster.cmd`：优先拍中央芯推送、分离、再入和载荷结尾。
- `StartCinematicBoosters.cmd`：优先拍侧芯分离、同步点火和双箭着陆。

摄影模式开始前请手动按 F2 隐藏 HUD。Stock kRPC 不能创建任意世界坐标的固定
地面相机，因此项目使用 Free、Chase 和 Orbital 相机模拟长焦及追踪镜头；真正
固定机位需要额外的相机模组。

## 飞行约束

当前三芯任务依赖以下载具约定：

- 左右侧芯同级分离，随后一级分离中央芯；载荷控制部件的 `decouple_stage` 为 -1。
- 左、右、中央芯各有 7 台液体发动机；上面级发动机数量不限。
- 左右侧芯各有 4 台用于分离的固体小火箭。
- 侧芯和载荷必须包含可工作的 `ModuleCommand`。
- 代码中的跑道与下程大陆坐标基于 Kerbin/KSC，换用不同天体或重缩放系统前需重标定。

默认优先级为：

1. 保留载荷推进剂并保持正东轨迹；
2. 两枚侧芯返回 KSC 跑道附近；
3. 中央芯完整落到正东下程大陆。

## 时间加速与控制权

- 正式脚本从不主动开启时间加速。
- 默认不允许加速；误触后脚本恢复 1×并继续，而不会退出任务。
- 使用 `--allow-warp` 时只允许玩家在安全滑行段手动加速，接近制动区会自动恢复 1×。
- 所有分离芯级使用各自的 Vessel 对象和发动机独立油门闭环控制，因此玩家可以
  切换观察载具；大量远距离载具同时物理模拟仍可能降低 KSP 帧率。
- 新版 PRE 候选补丁让远处已落稳的芯级退出物理加载，解除它们对载荷精度保护的阻塞。
  落地载具仍在存档/追踪站中，未删除、未自动正式回收；飞行中的芯级继续扩展范围。
  补丁尚需实飞验收，安装和限制见 [PRE 修复说明](PRE_PAYLOAD_FIX.md)。

## 测试

运行全部离线回归测试：

```bash
python -m unittest discover -v
```

当前测试覆盖结构识别、油门回退、重力转弯、返场迟滞、再入点火锁存、制动点、
末段水平速度、支腿与栅格舵、同步返场点火栅栏，以及摄影镜头事件选择。

## 已知限制

- 空气动力学、模组帧率和 Physics Range Extender 会影响落点重复性。
- KSP/kRPC 的正式“回收载具”会离开飞行场景；任务飞行期间不自动调用。三枚芯级落稳后仍留在存档中，玩家可在完成载荷任务后从追踪站回收。
- 摄影模式需要切换活动载具以使用 Stock 相机；复杂存档中可能比普通模式产生更多负载。
- 中央芯下程目标目前允许公里级误差，重点是结构完整和不被再入烧毁。
- 载荷分离后的圆化、轨道规划和任务载荷控制有意留给玩家。
